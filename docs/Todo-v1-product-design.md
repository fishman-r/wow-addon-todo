# Todo v1 产品与功能设计

> 状态：设计定稿
> 日期：2026-08-19
> 目标客户端：魔兽世界“泰坦重铸·时光服”，`Interface: 38002`
> 当前服务器内容阶段：P5
> 本文是 v1 的产品、交互、数据和验收基线；现有 Lua 原型及 README 中与本文冲突的内容均以本文为准。

## 1. 产品定义

Todo 是一个只面向 80 级角色的个人上线规划插件。玩家每次真正登录角色后，输入本次至少可玩的时长、工作日或假期模式，并手动选择开始区域。Todo 在保留缓冲时间的前提下，结合任务解锁、今日完成状态、明确可计算收益、系统推算耗时和区域移动时间，生成一份稳定、可执行的本次计划。

Todo 不是自动做任务工具，也不是全能任务数据库。它的定位是：

- 用有限且可信的数据给出时间预算内的计划；
- 只对明确价值进行金币估算；
- 自动识别优先；允许修正解锁、完成、区域和成本等明确字段，但所有预计耗时只读；
- 计划生成后保持稳定，只有用户主动重新规划才改变；
- v1 先保证流程完整、结果可解释和客户端可验证。

### 1.1 目标用户

- 在泰坦时光服游玩的 80 级玩家；
- 上线时间有限，希望减少“上线后不知道先做什么”的玩家；
- 希望兼顾金币效率、专业日常和假期团本的玩家。

### 1.2 核心成功标准

玩家应能在一次登录流程中完成以下闭环：

1. 输入本次条件；
2. 获得一份时间可容纳、来源可解释的计划；
3. 执行、完成、跳过或手动加入事项；
4. 让 Todo 学习任务、移动、团本和奖励袋数据；
5. 在价格或时间变化后，由玩家主动重新规划；
6. `/reload`、日常重置、周重置和目录升级不会静默破坏数据。

## 2. v1 范围

### 2.1 包含能力

- 工作日与假期模式；
- 本次可玩时长与固定 85% 自动规划预算；
- 手动选择开始区域；
- 固定、非限时、适合单人的 80 级日常；
- 主专业及烹饪、钓鱼等专业日常任务池；
- 假期团本推荐与时间预留；
- 明确奖励、材料成本、奖励袋、专业代币估值；
- 用户手动查询拍卖行后的被动价格缓存；
- 从已安装且兼容的主流拍卖插件手动导入已有价格数据；
- 按角色学习任务、路线和团本耗时；
- 区域级路线规划；
- 解锁、完成、团本锁定和数据来源展示；
- 本地待完善任务、目录升级和数据迁移；
- 简体中文 UI、斜杠命令、小地图入口和兼容性诊断。

### 2.2 明确不做

- 节日、周年庆及其他限时活动日常；
- 普通轮换任务的预测与概率建模；
- PvP、组队精英、随机地下城和周常的自动收益推荐；
- 分解、选矿、研磨、制造、兑换等加工后的理论收益；
- 多角色切换建议或跨角色规划；
- 坐标级导航、飞行点路径、炉石冷却、自动读取当前位置；
- 主动或批量查询拍卖行；
- 自动组队、报名、接取、交付或执行任务；
- 通用复杂任务编辑器；
- 历史会话回放、云同步和多语言；
- 声望、装备提升等主观价值的金币化。
- 任意“本次目标”或自定义非金币事项录入。

## 3. 核心概念

| 名称 | 定义 |
|---|---|
| 预设本次可玩时长 `T` | 用户确认本次计划使用的总时长 |
| 实际累计计时 `E` | 从生成计划起经过的真实墙钟时间，不封顶，允许大于 `T` |
| 算法剩余时间 `R` | `max(0, T - E)`；仅供重新规划计算，不作为主界面核心指标 |
| 自动规划预算 `B` | `0.85 × R`；只约束算法自动加入的内容 |
| 明确总收益 | 直接金币、明确物品、奖励袋期望值、专业代币用户估值之和 |
| 明确净价值 | 明确总收益减去明确必需材料机会成本和固定金币费用 |
| 任务效率 | 单项明确净价值 ÷ 任务自身耗时，不含共享区域移动 |
| 收益路线效率 | 收益任务明确净价值之和 ÷ 收益任务耗时与其区域移动耗时之和 |
| 本次计划明确价值率 | 全部明确净价值 ÷ 全部计划占用时间；包含不估值的团本时间，属于已知价值下限 |
| 状态未知 | 解锁或今日完成状态无法由客户端或用户明确确认 |
| 固定保留项 | 进行中项目、已确认团本、用户手动加入的收益任务 |

### 3.1 三种计时器

三种计时器必须完全区分：

1. **窗口倒计时**：只控制非持久窗口 60 秒后隐藏；有效输入或操作重置为 60 秒，鼠标悬停不暂停。
2. **会话计时**：从生成计划开始按真实墙钟运行；聊天、挂机、关闭窗口、输入和普通操作均不暂停。
3. **学习计时**：用于任务、区域移动和团本历史样本，可因移动、异常、完成、跳过或人工操作改变。

## 4. 等级与客户端边界

- 只有当前角色等级正好为 80 时启用 Todo 功能。
- 79 级及以下角色只显示“Todo 仅支持 80 级角色”。
- 非 80 级角色不打开主界面、不推荐、不计时、不采集拍卖价格或奖励袋样本。
- TOC 目标为 `Interface: 38002`。
- “能够加载”不等于“已经兼容”；必须完成第 20 节的时光服真机验收后，才能宣称已兼容。
- 所有游戏 API 应集中通过 `Compat38002` 兼容层调用，业务逻辑不得混用未经确认的 Retail、普通 Classic 或旧私服 API 假设。

## 5. 会话初始化

### 5.1 触发规则

- 每次真正登录角色或切换角色，展示“生成本次计划”界面。
- 上次模式、声明时长和开始区域按角色预填，但用户必须确认后才生成。
- `/reload` 能可靠识别时恢复当前会话；无法确认是重载、重新登录还是异常恢复时，展示已预填界面，并提供“继续上次计划”。不得静默恢复旧计时。
- 战斗中不弹出；脱离战斗后只弹一次。
- 生成计划时保存预设本次可玩时长 `T`，把实际累计计时 `E` 置为 0，并启动会话计时。

### 5.2 输入项

| 输入 | 规则 |
|---|---|
| 模式 | 工作日或假期；使用上次值预填，用户确认 |
| 至少可玩时长 | 必须大于 0；生成时保存为预设本次可玩时长 `T` |
| 开始区域 | 必须手选，不读取当前位置 |
| 团本 | 按模式和时长显示；用户可接受、取消或追加 |

界面不提供“本次目标”或任何预计耗时输入框。预设本次可玩时长 `T` 是用户声明的时间预算，不属于系统预计耗时。

### 5.3 开始区域

- 下拉选项来自任务目录区域与主要枢纽。
- 记住当前角色上次选择，但每次真正登录仍需确认。
- 提供“其他/不计算首段路程”。
- 选择该项时，只免除起点到第一个区域的移动时间，并标记“首段路程未计入”。
- 后续区域间移动仍必须存在系统可用的耗时来源。
- v1 不允许任意文本区域，也不自动读取当前地图。

### 5.4 预计耗时自动推算

- 任务、区域移动和团本的预计耗时均由系统计算并只读展示，用户不能输入、修改或覆盖分钟数。
- 任务耗时来源依次为：当前角色有效样本中位数、内置参考、缺失。
- 有向区域移动耗时来源依次为：当前角色有效样本中位数、内置参考、缺失。
- 团本耗时来源依次为：当前角色完整清团样本中位数、默认值；25 人团本默认 120 分钟，宝库默认 30 分钟。
- 每个预计耗时同时展示来源。开始、结束、交付、到达等人工操作只产生学习样本，不直接设置预计耗时。
- 任务或必需移动同时缺少有效样本和内置参考时，标记“耗时数据缺失”，不得自动推荐，也不能通过手工输入耗时加入计划。
- 生成参数变化时重新预演预计计划用时；计划生成后继续遵守稳定计划规则，只有主动重新规划才采用新的系统推算结果。

## 6. 模式规则

### 6.1 工作日

- 不自动推荐任何团本，包括宝库。
- 自动收益任务的单项预计耗时不得超过 30 分钟。
- 超过 30 分钟的任务仍显示在全部候选中，用户可以手动加入。
- 在满足硬条件后，仍以总明确净价值最大化，而不是固定限制任务数量。

### 6.2 假期

- 收益任务没有 30 分钟单项上限。
- 声明时长少于 3 小时：不展示 25 人团本；若 85% 预算能容纳 30 分钟，可自动推荐宝库。
- 声明时长达到 3 小时：显示完整团本列表，“考虑大型团本”默认勾选。
- 系统最多自动选择一个能够放入当前剩余自动预算的最高优先级团本。
- 用户可取消或手动追加多个团本；手动确认后允许超时，但必须警告。

## 7. 任务目录

### 7.1 目录原则

- 目录应尽量完整覆盖符合 v1 范围的任务，而不是只维护少量预设高收益任务。
- 推荐算法负责筛选，目录不预先用主观“高收益”裁剪。
- 不确定内容不猜测、不伪造；进入“待完善任务”。
- P5 为当前内置阶段，P1–P5 均视为开放；设置中不提供阶段切换。
- 后续服务器内容变化通过 Todo 版本更新目录。

### 7.2 固定日常的必需字段

每项固定日常只有在以下字段完成核实后，才能进入正式自动候选：

- questID 与中文名称；
- 所属区域和目录顺序；
- 内容阶段；
- 阵营、声望、前置任务、专业和技能等解锁条件；
- 互斥组与前置依赖；
- 固定金币、固定物品、多选奖励；
- 必需材料、数量和固定金币成本；
- 内置参考耗时；
- 数据来源、目录版本和核实状态。

### 7.3 专业任务池

- 主专业及烹饪、钓鱼等次级专业均可纳入。
- 当前角色未学习对应专业或技能不足时，视为明确未解锁。
- 每个专业池是一个推荐单位，池内可能任务全部直接展示。
- 未识别今天具体任务时：收益使用池内已核实具体任务的算术平均；耗时优先使用当前角色该池历史中位数，否则使用内置参考。
- 只要池内任一匹配具体任务今日完成，整个类别视为今日完成。
- 用户可手选今天的具体任务；接取后也可自动识别。
- 手动选择优先于自动识别，持续到服务器日常重置。
- 识别具体项只刷新详情；重新规划后才按具体项改变选择。

### 7.4 解锁与完成状态

| 条件 | 自动推荐处理 |
|---|---|
| 解锁=否，或今日完成=是 | 明确不可执行，不自动推荐 |
| 解锁=是，且今日完成=否 | 明确可执行，进入第一阶段优化 |
| 解锁或完成任一未知，且无明确不可执行条件 | 状态未知，只在第一阶段完成后用剩余时间补充 |

- 自动识别优先；用户可以按字段修正，手动值优先并可恢复自动。
- 登录时能由客户端确认已完成的任务直接过滤。
- 交付匹配 questID 后自动标记完成。
- 手动“完成/未完成”覆盖持续到服务器日常重置。
- 当前计划中的完成项保留原位、打勾变灰。
- 全部候选中的完成项移入折叠的“今日已完成”。

### 7.5 前置与互斥

- 前置未满足的任务不自动入选，并展示缺少条件。
- 每个互斥组最多选择一个任务。
- 自动算法在互斥组内选择对本次计划更合适的候选。
- 手动加入冲突项时必须先替换已有项，不能保存明显不可能同时成立的计划。

### 7.6 目录外任务

- 新发现的日常先进入“待完善任务”，记录 questID、名称、可明确归因的奖励和可用样本。
- 默认不自动计时；用户点击“开始记录此任务”后才进入学习集合。
- 不能因完成一次就自动认定它固定、非限时、非轮换且适合单人。
- 用户确认“固定日常、非限时、可单人”并补齐区域和成本后，只有系统已取得内置参考或有效学习样本时，才能启用为本地候选；用户不能补填耗时。
- 正式目录后来包含同一 questID 时自动合并，不产生重复项。

## 8. 团本设计

### 8.1 固定顺序

团本列表始终保持以下顺序，不因收益、锁定进度或预计耗时暗中改变：

| 顺序 | 阶段 | 团本 |
|---:|---|---|
| 1 | P5 | SW（太阳井高地） |
| 2 | P5 | ZAM（祖阿曼） |
| 3 | P4 | TOC（十字军的试炼） |
| 4 | P4 | ZG（祖尔格拉布） |
| 5 | P3 | NAXX（纳克萨玛斯） |
| 6 | P3 | 黑曜石圣殿 |
| 7 | P3 | 永恒之眼 |
| 8 | P2 | 毒蛇神殿 |
| 9 | P2 | 风暴要塞 |
| 10 | P1 | MC（熔火之心） |
| 11 | 独立 | 宝库 |

### 8.2 人数、难度与耗时

- 常规团本为 25 人、单一难度；UI 不显示普通/英雄或人数选择。
- 宝库为 21 人、单一难度，作为一个完整推荐项，不按首领拆分。
- 25 人团本默认预计 120 分钟；宝库默认预计 30 分钟。
- 团本预计耗时包含集合、前往、实际活动到本次结束的全部占用时间。
- 团本不进入日常区域路线，不再额外计算移动时间。

### 8.3 自动选择

- 先考虑自动确认“本周未完成”的团本，再考虑状态未知的团本；组内仍保持固定版本顺序。
- 本周全部完成的团本移入“本周已完成”，不自动推荐。
- 部分进度团本保留原版本优先级。
- 自动最多选择一个；用户可手动追加。
- 团本是时间预留，不进行金币估值，也不反向影响收益任务的金币效率。

### 8.4 锁定与进度

- 登录后请求团本信息，等待异步更新事件后再读取。
- 能取得实例和首领明细时显示自动状态。
- 只有实例锁定而没有首领明细时显示“已产生锁定，进度未知”。
- 无法映射泰坦自定义实例时显示“状态未知”，允许手动修正。
- 用户可手动标记未打、部分进度或已完成；覆盖持续到服务器周重置。
- 部分进度不按剩余首领比例自动缩短耗时；继续使用系统自动推算值，并标记为保守估计。

### 8.5 团本耗时学习

- 来源优先级：当前角色最近 20 次有效完整样本中位数 > 默认值。
- 团本由用户手动点击“开始团本”和“结束本次团本”。
- 只有本次开始时为零进度，并在本次完整清团，才写入完整团本耗时样本。
- 从已有部分进度打到结束，或本次只完成部分进度，不写入完整样本。
- 异常样本进入待确认。

## 9. 收益估值

### 9.1 单个物品价值

```text
有当前生效的市场价格：
max(商店售价, 市场税前单位价 × (1 - 市场手续费))

没有市场价格、但有手动价：
max(商店售价, 手动税前单位价 × (1 - 市场手续费))

两者都没有：
商店售价；不可出售则为 0
```

- 拍卖押金不计入成本，因为成功出售时会返还。
- 手动价格含义统一为预计拍卖行税前单位价。
- 市场价格可以来自 Todo 对原生拍卖行搜索的被动缓存，也可以来自兼容拍卖插件的只读导入；两者必须保留来源，不得混写。
- 有市场价格后仍保留手动价，但只作为市场价格缺失时的备用。
- 绑定且不可出售的物品价值为 0；绑定装备最多使用商店售价。
- 不计算分解、制造或兑换后的价值。

### 9.2 任务收益与成本

```text
明确总收益 =
  直接金币
  + 固定奖励物品价值
  + 多选一奖励中实际指定或最高可变现的一项
  + 奖励袋历史期望价值
  + 专业代币数量 × 当前角色手动代币单价

明确净价值 =
  明确总收益
  - 必需材料机会成本
  - 固定金币费用
```

规则：

- 多选一只计算一件；默认使用明确可变现净值最高项，用户可手选计划领取项。
- 声望、荣誉、徽章、牌子及其他绑定货币只展示，不估值。
- 专业代币按角色、按代币类型手动设价；未设置为 0 并提示。
- 未知奖励按 0，已知收益为保守下限，仍可自动推荐。
- 奖励袋无样本时按 0，仍可自动推荐。
- 必需材料或固定金币成本未知时，净价值不可计算，不自动推荐。
- 已拥有、存银行或自行采集的材料仍按机会成本扣除。
- 不计算飞行费、修理、药剂、食物等难以明确归属的通用开销。
- 任务成本以内置目录或用户修正为准，不通过背包差值自动学习。

### 9.3 固定奖励学习

- 初次推荐使用内置奖励。
- 实际交付后，只在金币或物品能够明确归因时写入同服务器实测覆盖。
- 最新可信实测优先于内置值，并记录更新时间。
- 事件、奖励界面和背包变化互相矛盾或混入其他来源时，本次实测作废，不覆盖目录。
- 用户可删除实测覆盖，恢复内置值。

## 10. 市场价格数据

### 10.1 Todo 原生被动采集

- Todo 永不主动发送拍卖查询。
- 不提供批量查询、更新所选或自动扫描按钮。
- 只有 80 级角色在原生拍卖行手动搜索后，Todo 才被动读取公开结果。
- 估值数据页展示生效价格、来源、来源数据时间、导入/采集时间、样本数和缺价物品清单。

### 10.2 Todo 原生缓存计算

- 只接受与目标 itemID 明确匹配、单位价格大于 0、可以购买的有效挂单。
- 取单位价格最低的 20 条有效挂单计算中位数。
- 不足 20 条时使用全部有效挂单，并显示实际样本数和“样本较少”。
- 每次成功手动搜索用本次中位数直接替换旧缓存，不做历史平均和走势图。
- 搜索失败、空结果或物品不明确时保留旧缓存；无旧值则继续缺价。
- 缓存永不过期，直到用户再次成功搜索、删除或清理。
- 保存 itemID、税前单位价、更新时间、样本数和市场键。

### 10.3 兼容拍卖插件只读导入

- “估值数据”页检测当前已加载、具有已验证适配器的主流拍卖插件；检测本身不读取或复制价格库。
- 只有用户点击“导入所需物品价格”才执行导入，不在登录、打开窗口、重新规划或定时器中自动导入。
- 导入只读取 Todo 当前目录奖励、成本、奖励袋内容和缺价清单实际需要的 itemID，不复制第三方插件的完整数据库。
- 优先调用第三方插件公开且稳定的只读 API。没有已验证 API 的版本不直接猜测其 SavedVariables 私有结构，并显示“不兼容此版本”。
- 适配器必须把价格规范化为当前市场的税前单位价；无法确认 itemID、单位、市场或价格字段语义时跳过该物品，不使用猜测值。
- 每条记录保存：提供方、插件版本、提供方价格指标、市场键、itemID、税前单位价、来源数据时间（若提供）、本次导入时间和适配器版本。
- 导入不向第三方插件写数据、不触发拍卖查询，也不改变第三方插件配置。
- 每个提供方调用都通过保护调用隔离；先写临时结果再提交。单项或提供方失败不得污染旧记录。
- 完成后汇总“成功 N 项、缺失 N 项、跳过 N 项、错误 N 项”，并允许查看逐项原因。

v1 适配器范围：

| 提供方 | v1 定位 | 价格口径与边界 |
|---|---|---|
| Auctionator | 首个 Titan 候选正式适配器；必须在 38002 真机验收通过后才标记“兼容” | 通过公开 `Auctionator.API.v1.GetAuctionPriceByItemID` 读取最近扫描最低单位价；不是 Todo 的最低 20 条中位数 |
| TradeSkillMaster | 保留公开 API 兼容槽；当前不承诺 Titan 可用 | 若未来通过 38002 验收，必须明确所选价格源，例如 `DBMarket`，不得标成实时最低价 |
| Auctioneer | 保留公开 API 兼容槽；当前不承诺 Titan 可用 | 若未来通过 38002 验收，导入其市场价值及市场键，不得标成最低一口价 |

- 不从磁盘读取另一个插件的 SavedVariables，不接入桌面程序或网站数据，也不承诺导入插件全量物品。

### 10.4 生效来源与新旧冲突

- Todo 原生缓存与各外部提供方快照分别保存；外部导入数据不得冒充“Todo 原生缓存”。
- 同一 itemID 的估值优先级固定为：Todo 原生缓存 > 用户当前选择的外部提供方快照 > 手动税前价 > 商店售价。
- 外部导入只补充 Todo 原生缓存缺失的物品，不覆盖也不与 Todo 原生缓存或其他提供方取平均。
- 用户在导入时选择一个外部提供方；后续再次选择其他提供方并成功导入，才切换“当前外部提供方”。
- 提供方能给出来源扫描时间/年龄时必须保存并展示；不能提供时显示“来源数据时间未知”，不得用导入时间冒充扫描时间。
- 任何市场快照都不设置有效期，在下一次成功原生搜索、再次导入、用户切换来源、删除或清理前持续参与估值。
- 手动税前价只在没有生效市场价格时使用；商店售价始终作为价值下限。
- 价格来源变化只刷新“当前估值”，不改变已经生成的计划成员和顺序。

### 10.5 手续费与市场隔离

- Todo 内置经真机核实的当前市场手续费默认值。
- 用户可按服务器市场修正手续费。
- 修改手续费只刷新估值；当前计划成员和顺序不自动变化。
- 市场拓扑无法确认时，保守使用“服务器 + 阵营/用户市场配置”隔离，不自动跨市场共享。
- 只有客户端实际暴露逐挂单数据时，才能实现“最低 20 条中位数”；若只提供聚合最低价，自动采集关闭并保留旧缓存或手动价，不能伪装成 20 条样本。

## 11. 奖励袋

- 所有奖励袋在没有真实样本前价值为 0，不提供手动预估价。
- 检测到已知袋子减少后，只记录能够明确关联的直接金币和物品数量。
- 连续开启多个同一种袋子，可把总内容与实际开启数量作为一批样本累计。
- 混入其他种袋子、任务奖励、交易、邮件或来源不明物品时，整批作废。
- 保存原始物品分布、数量和累计袋数，不保存冻结金币估值。
- 原始开袋分布与样本数全账号共享；估值使用当前角色所属服务器市场的价格动态重算。
- 第一个有效样本立即参与以后排名；累计少于 5 袋时显示“低样本，仅供参考”。
- 开袋物品缺价时按 0，并显示“至少 X 金 + N 项未知物品”。

## 12. 时间学习

### 12.1 数据来源优先级

| 数据 | 优先级 |
|---|---|
| 任务耗时 | 当前角色有效样本中位数 > 内置参考 > 缺失 |
| 有向区域移动 | 当前角色有效样本中位数 > 内置参考 > 缺失 |
| 团本耗时 | 当前角色完整样本中位数 > 默认值 |

- 每项任务、每条有向路线和每个团本最多保留最近 20 个有效样本。
- 任务和路线耗时按角色保存，不跨角色混用。
- 所有预计耗时只读；开始、结束、交付、到达等人工操作仅形成学习样本，不能直接写入预计耗时。

### 12.2 任务计时

- 本次计划中的匹配任务被接受时自动开始学习计时。
- 已提前接取的任务必须点击“开始计时”。
- 只有本次计划中已经开始、尚未交付或手动结束的任务参与并行分摊。
- 任务日志中的其他已接任务不参与。
- 交付、跳过或手动停止后立即退出集合。
- 未完成便跳过或停止，不形成有效任务样本。
- 任务自身耗时包含区域内完成目标与交付所需的本地移动，不包含显式的跨区域路线节点。

### 12.3 并行动态平均分摊

对每个并行集合不变的时间片：

```text
每个活动任务分配耗时 = 时间片长度 Δt ÷ 当时活动任务数 N
```

- 活动集合发生变化即开始新的时间片。
- 原始分摊记录总和等于非移动的有效学习时间。
- 某任务样本被丢弃时，只丢弃它已经分到的部分，不追溯重分配给其他任务。
- 正常交付或用户明确确认完成后，才形成有效任务样本。

### 12.4 区域移动计时

- 点击路线节点“开始前往”后，只累计区域移动时间，任务学习计时暂时停止。
- 当前任务状态保留，但移动时间不向并行任务分摊。
- 目标区域中第一个计划任务被接受/手动开始，或用户点击“已到达”时，结束移动计时。
- 全程不读取当前地图或位置。
- 实际累计计时 `E` 始终按墙钟增长，不受移动计时或任务计时状态影响。

### 12.5 异常样本

- 至少已有 3 个有效样本时，以当前中位数为基准；否则使用内置参考。
- 新样本短于基准 25%，或长于基准 400%，进入“待确认”。
- 游戏 AFK 标记持续至少 5 分钟、掉线、计时跨真正登录会话，也进入待确认。
- 待确认样本不参与中位数，用户可保留或丢弃。
- 没有基准时先正常收录，不做倍数判断。
- 样本无效或被删除不会补回会话时间。

## 13. 区域路线

- 路线只建模任务所属区域，不做坐标或路径寻路。
- 移动关系是有向的，例如“达拉然→冰冠冰川”与反向分别保存。
- 同一区域的任务共享一次跨区移动成本。
- 从用户手选开始区域出发，结束于最后一项任务的交付处，不计算返程。
- “全部候选”的任务效率不包含共享路程。
- “本次计划”把移动显示为独立节点，并显示收益路线效率。
- 收益路线标题只显示任务与移动的合计预计分钟数，不在标题中拆分两类耗时；底层仍分别保存并参与算法与学习。
- 自动规划使用的每条移动边必须具有角色中位数或内置参考。
- 未知路线不允许默认为 0，也不进入自动规划。
- 手动加入若引入耗时来源缺失的移动边，则暂不允许加入；需先形成有效移动样本或由目录补齐，不提供本次耗时输入框。
- “其他/不计算首段路程”是唯一合法的零移动例外。

## 14. 推荐算法

### 14.1 85% 预算语义

```text
算法剩余时间 R = max(0, 预设本次可玩时长 T - 实际累计计时 E)
自动规划预算 B = 0.85 × R
```

- 85% 是算法自动加入内容的硬上限，不是用户已确认团本或手动加入收益任务的硬上限。
- 用户修改“预设本次可玩时长”时直接更新 `T`；实际累计计时 `E` 不归零、不回退。
- “再玩 X 分钟”是便捷操作，等价于把 `T` 设置为 `E + X`。
- 每次重新规划都用当时的 `R × 85%`，不能使用“初始预算减去经过时间”。
- `E` 可以大于 `T`；此时 `R=0`，自动规划不再加入新内容，但会话计时继续增长。

### 14.2 入选/保留优先级

以下优先级决定是否保留或入选，不直接决定最终路线展示顺序：

1. 已经进行中的项目；
2. 用户已经确认的团本；
3. 用户手动加入的收益任务；
4. 算法自动选择的收益任务。

- 前三类为固定保留项。
- 固定保留项先占用预算；超过 `B` 时全部保留、提示预计超时，并停止自动追加。
- 自动收益任务不能主动突破 `B`。
- 团本只有在自动选择阶段确实能放入当前剩余自动预算时才会自动勾选；用户确认后转为固定保留项。
- 不提供“本次目标”输入项，也不设置“本次重点目标”独立模块。所有入选事项都进入同一份“本次计划”列表。
- 带区域收益任务按路线位置展示；团本作为普通时间块行展示，不参与收益路线排序。
- 团本时间块仍包含集合、前往与活动时间，不再叠加日常路线移动。

### 14.3 自动候选过滤

自动候选必须满足：

- 当前角色等级为 80；
- 属于当前 P5 目录且非限时；
- 不存在明确未解锁或今日已完成；
- 任务自身耗时可用；
- 必需成本完整；
- 必需路线耗时可用；
- 不违反前置和互斥；
- 工作日单项不超过 30 分钟；
- 已知收益下限计算出的任务效率达到当前角色门槛。

门槛规则：

- 默认留空，仅排除明确净价值小于或等于 0 的任务。
- 用户可设置每角色最低净金币/小时。
- 低于门槛的任务仍显示在全部候选中，可手动加入。
- 成本未知时净价值不可计算，不参与门槛比较。

### 14.4 两阶段可执行性

1. 先只使用明确可执行且今日未完成的任务优化；
2. 还有预算时，再使用状态未知任务补充。

未知状态不能用虚构加权去篡改单项金币/小时；只影响自动选择阶段。

### 14.5 优化目标与确定性

- 项目不可拆分，推荐数量没有上限。
- 在计入有向区域移动成本后，以预算内明确净价值总和最大为目标。
- 同总价值时依次偏好：
  1. 总耗时更短；
  2. 跨区更少；
  3. 数据更完整；
  4. 内置目录顺序更靠前。
- 相同输入与相同数据快照必须得到相同结果。
- 没有项目能完整放入时不强塞；展示最接近预算的候选和预计超出时间。

### 14.6 手动加入数据不完整项目

- 任务耗时或必需移动耗时缺失时，不允许手动加入；用户不能通过填写预计耗时绕过。首段“其他”例外除外。
- 成本未知时允许手动加入，但显示“净价值无法估算”。
- 价值不完整项目不进入计划明确净价值合计，也不显示虚假的金币/小时。
- 整体计划显示“另有 N 项价值不完整”。

## 15. 计划执行与重新规划

### 15.1 稳定计划

- 生成后冻结计划成员、顺序、路线和预留时间。
- 完成项保留原位、打勾变灰，不自动重排。
- 不设置“提前完成可追加”模块，也不因进度提前自动加入任何内容。
- 用户需要追加事项时进入“全部候选”，通过检索找到候选并手动加入。
- 进度落后时只警告，不自动删除。
- 价格、袋子均值、代币值和实测奖励变化时，只刷新“当前估值”。
- 任务行与顶部同时保留“生成时估值”和“当前估值”，并标记数据已变化。
- 只有用户点击“重新规划”才改变成员、顺序和路线。

### 15.2 完成与跳过

- “本次跳过”只对当前会话生效，不等于今日完成。
- 跳过项保留原位置并可撤销；重新规划时排除。
- 下次真正登录自动恢复为候选。
- 被跳过任务后来实际交付时，以完成状态为准。
- 80 级角色交付目录任务时，即使不在计划中，也更新完成与可信实测奖励。
- 计划外任务只有主动计时后才保存耗时。
- 会话汇总区分计划内完成和计划外完成。

### 15.3 手动加入

- 任务区域已在路线中：插入该区域任务组末尾。
- 任务区域不在路线中：把新区域和移动节点追加到路线末尾。
- 团本作为普通时间块行追加到统一计划列表，不建立独立模块。
- 不自动重排原有任务。
- 手动加入低于收益门槛或工作日超过 30 分钟的任务合法。
- 产生超时时保留并警告。
- v1 不支持拖动日常路线；重新规划才重新优化区域顺序。

### 15.4 重新规划

- 先排除已完成和本次跳过。
- 进行中项目必须保留。
- 进行中项目预计剩余耗时为“原预计耗时 - 本次有效计时”。
- 已超过系统预计但尚未结束时标记“预计已超时”；剩余时间无法可靠推算，因此该项目结束前重新规划不再自动填充新事项，也不要求用户补填时间。
- 使用最新状态、价格、任务值、路线值和新的 `R × 85%` 重新计算。
- 用户可以在重新规划前修改预设本次可玩时长 `T`，或使用“再玩 X 分钟”把 `T` 设为 `E + X`。

### 15.5 超过预设时长

- 当 `E ≥ T` 时不关闭计划，也不清空未完成项。
- 顶部继续显示“实际累计计时 / 预设本次可玩时长”，例如 `4:17 / 4:00`，并标记“已超出 17 分钟”。
- 实际累计计时不封顶，窗口隐藏、聊天、挂机、输入和操作都不会暂停。
- 不自动追加，也不假设玩家继续。
- 此时内部 `R=0`、`B=0`；用户可修改 `T` 或使用“再玩 X 分钟”后主动重新规划。

### 15.6 跨重置

- 服务器日常或周重置发生时，当前计划保持冻结。
- 显示“服务器已重置，当前计划基于重置前状态”。
- 自动/手动周期状态按新周期重新读取或清除。
- 正在进行的学习样本停止并进入待确认，避免跨两个周期。
- 用户点击重新规划后才生成新周期计划。

## 16. 信息架构与交互

### 16.1 主界面页签

固定四个页签：

1. **本次计划**：统一计划列表、本次用时、完成/跳过、手动加入和重新规划。
2. **全部候选**：模糊检索、任务效率排序以及可执行、状态未知、数据不完整、未解锁、今日已完成分组。
3. **估值数据**：Todo 原生缓存、外部拍卖插件导入、缺价物品、奖励袋样本、专业代币单价。
4. **设置**：UI 偏好、收益门槛、手续费、解锁、任务修正、待确认样本和数据清理。

### 16.2 本次计划顶部

展示：

- 模式与手选开始区域；
- 本次用时：`实际累计计时 E / 预设本次可玩时长 T`；
- 85% 自动预算、已规划时间与预计结束时间；
- 计划生成时明确净价值与当前明确净价值；
- 收益路线效率；
- 本次计划明确价值率，并标注它是已知价值下限；
- 计划内/计划外完成数量与估算价值；
- 价值不完整项目数量。

“本次用时”的分子始终继续累计，允许超过分母；主界面不把算法剩余时间 `R` 作为核心指标。

### 16.3 统一计划列表

- 不显示“本次目标”“本次重点目标”和“提前完成可追加”模块。
- 团本、收益任务和跨区移动共同出现在一份计划列表中；类型通过行图标、标签和操作区区分。
- 团本是普通时间块行；收益任务和移动节点保持路线顺序。
- 收益路线分组标题只展示一个合计耗时，例如“总计 57 分钟”，不再拆成“任务 39 分 · 移动 18 分”。
- 单项行展示只读预计耗时及其来源，不提供编辑或修正入口。

### 16.4 任务行与详情

摘要格式：

```text
[区域] 任务名称
明确净价值 X 金 · 任务耗时 Y 分钟 · 任务效率 Z 金/小时
```

展开后展示：

- 直接金币、固定物品、多选奖励；
- 奖励袋均值和样本数；
- 专业代币数量与用户单价；
- 必需材料、固定金币成本；
- 生效市场价格、提供方、口径、来源数据时间、采集/导入时间和可用样本数；
- 缺失估值与是否为收益下限；
- 任务、路线、解锁、完成等字段的数据来源；
- 固定任务详情或专业池全部可能任务；
- 前置、互斥、状态和修正入口。

### 16.5 全部候选检索与分组

- “全部候选”顶部固定提供搜索框，列表加载完成后即可检索，不要求到达区域或切换分组。
- 检索字段包括：任务名称、区域、专业、活动类型和 questID。
- v1 的模糊检索采用大小写不敏感、忽略首尾与重复空格的包含匹配；多个空格分隔关键词之间为 AND。
- v1 不承诺拼音/首字母、错别字纠正或编辑距离匹配。
- 检索只过滤当前展示，不改变原有分组、任务效率排序、计划或推荐结果。
- 搜索时命中的折叠分组临时展开，并显示“匹配 X / 全部 Y”；清空后恢复原折叠状态。
- 搜索框为空时展示全部；无匹配时显示“没有找到候选”，并提供清空搜索；搜索词仅属于当前界面状态，不长期保存。

- 可执行：按任务效率降序。
- 状态未知：独立标记，按任务效率降序。
- 低于门槛：仍可查看和手动加入。
- 成本或耗时不完整：只展示，说明阻止自动推荐的原因。
- 未解锁：底部灰显并说明条件。
- 今日已完成：折叠分组。
- 列表使用滚动，不设候选数量上限。

### 16.6 估值数据页

- 顶部展示当前生效价格及来源筛选，物品详情可查看 Todo 原生缓存、各外部插件快照、手动备用价和商店售价。
- “拍卖插件导入”卡片列出已检测提供方、插件版本、适配状态、价格指标、来源数据时间和上次导入时间。
- 只有显式按钮“导入所需物品价格”；不提供扫描全库、自动导入或触发第三方查询的入口。
- 导入完成展示成功、缺失、跳过与错误数量，并提供逐项报告；无兼容插件时解释可继续使用原生手动搜索或手动价。
- 每个生效价格都显示来源标签；外部价格不显示为 Todo 自己计算的“最低 20 条中位数”。

### 16.7 修正数据

任务详情中的“修正数据”允许逐字段修改：

- 解锁状态；
- 所属区域；
- 必需材料、数量与固定金币成本；
- 今日完成状态。

可修正字段显示 `自动 / 内置 / 实测 / 手动` 来源，可单独恢复自动值。预计耗时仅显示 `实测中位数 / 内置参考 / 默认值 / 缺失`，不可编辑；区域和固定成本修正按服务器共享，耗时样本与解锁按角色保存。

### 16.8 窗口行为

- 非常驻模式：窗口 60 秒后自动隐藏。
- 鼠标悬停、输入或操作不暂停倒计时；有效输入或操作把窗口倒计时重置为 60 秒。
- 常驻模式：关闭窗口倒计时，并按账号记住。
- `/todo` 和小地图按钮可重新打开。
- 小地图按钮左键开关主窗口，右键打开设置，可在设置中隐藏。
- 普通缺价、低样本、未知状态不弹阻塞窗口，也不播放声音或刷聊天框。
- 超时、服务器重置和计划数据失效用醒目横幅。
- 加载失败、关键版本不兼容等错误才写入聊天框。

### 16.9 视觉风格与组件规范

- Todo 采用参考 ElvUI 的深色、扁平、紧凑视觉语言，但不复制 ElvUI 的代码、材质、字体、图标或 API，也不把 ElvUI 设为依赖；无论用户是否安装 ElvUI，Todo 都应独立工作。
- 主背景使用 `#101010`，次级面板使用 `#1A1A1A` / `#222222`，外沿为黑色并辅以 `#333333` 内描边；主要交互强调色为 `#1785D1`。
- 主文字使用 `#E6E6E6`，次要文字使用 `#999999`；成功、警告、错误与金币分别使用绿色、黄色、红色与浅金色。状态不能只靠颜色表达，必须同时带文字或图标。
- 固定使用暗色主题。组件以 1 像素硬边、0–2 像素圆角和轻微内描边为主；不使用网页式白色卡片、玻璃效果、渐变、大圆角、胶囊标签或大面积柔和阴影。
- 信息密度接近游戏内整合 UI：标题栏、分页、任务行和表单采用紧凑间距；默认只展示决策必需信息，次级说明通过任务详情展开。
- 游戏实现使用客户端内置字体或 `GameFontNormalSmall` 同等级字体对象，不随插件分发 ElvUI 字体。按钮、输入框、分页和状态块均提供正常、悬停、按下、禁用与选中状态。
- 游戏实现只使用 38002 已确认可用的模板、纯色材质与像素对齐，不读取 ElvUI SavedVariables，不修改 ElvUI 或暴雪全局样式。

## 17. 数据作用域与生命周期

### 17.1 作用域

| 作用域 | 数据 |
|---|---|
| 全账号 | 奖励袋原始分布与样本数；窗口位置、大小、常驻等 UI 偏好 |
| 同服务器实际市场 | Todo 原生拍卖缓存、外部拍卖插件价格快照及来源元数据、生效来源选择、手动物品价、手续费、任务实测奖励、任务固定成本与区域修正 |
| 当前角色 | 解锁、今日完成、专业代币值、任务/路线/团本有效耗时样本、收益门槛、上次模式/时长/开始区域 |
| 当前会话 | 会话开始墙钟、预设时长 `T`、累计用时恢复信息、模式与开始区域输入、计划快照、手动加入、跳过、计时状态 |

完成状态和团本锁定即使由客户端读取，也按角色展示和覆盖。

### 17.2 数据保留

- 任务、路线、团本各保留最近 20 个有效耗时样本。
- 奖励袋保存聚合内容分布，不保存每次开启日志。
- 每个市场只保留 Todo 当前原生缓存和各外部提供方当前快照，不保存同一来源的价格历史。
- 不保存完整会话回放。
- Todo 更新或普通重装不得主动清除 SavedVariables。

### 17.3 周期清理

- 今日完成手动覆盖、专业今天具体任务选择：服务器日常重置时清除。
- 团本手动锁定覆盖：服务器周重置时清除。
- 价格、奖励袋、任务奖励、耗时、解锁和长期修正不因日/周重置清除。

### 17.4 目录与数据库升级

- 新目录不覆盖用户手动的非耗时字段、实测数据、价格和有效耗时样本。
- 内置字段变化时展示新旧差异，并允许按字段恢复新版内置值。
- 本地任务与正式目录同 questID 自动合并。
- 数据结构尽量自动迁移；无法迁移的字段单独提示，不整库清空。
- 内置目录永不被用户清理操作删除。

### 17.5 数据清理

设置中分别提供：

- 结束/清理当前会话；
- 清理当前角色学习数据；
- 清理当前服务器价格；
- 清理奖励袋样本；
- 恢复任务自动值；
- 清除全部 Todo 用户数据。

所有删除操作二次确认，并明确范围与不可撤销性。v1 不提供容易误触的直接清库命令，也不做云备份或 Todo 数据的通用导入导出；第 10.3 节受控的拍卖插件价格导入是唯一例外。

## 18. 概念数据模型

以下是设计层级，不约束具体 Lua 表名：

```text
TodoDB
├─ meta
│  ├─ schemaVersion
│  ├─ catalogVersion
│  └─ lastMigration
├─ account
│  ├─ uiPreferences
│  └─ rewardBagDistributions[itemID]
├─ markets[marketKey]
│  ├─ nativeAuctionPrices[itemID]
│  ├─ externalAuctionPrices[provider][itemID]
│  ├─ activeExternalProvider
│  ├─ manualItemPrices[itemID]
│  ├─ commissionRate
│  ├─ observedQuestRewards[questID]
│  └─ taskCorrections[questID]
├─ characters[characterKey]
│  ├─ preferences
│  ├─ tokenValues[tokenID]
│  ├─ unlockOverrides
│  ├─ cycleStates
│  ├─ taskDurations
│  ├─ routeDurations[fromRegion][toRegion]
│  ├─ raidDurations
│  └─ activeSession
└─ localPendingTasks[questID]
```

要求：

- 角色键优先使用稳定角色标识；无法使用时回退到服务器、阵营和角色名组合。
- 市场键必须表达实际服务器市场；无法确认跨阵营统一时保守隔离。
- 当前计划必须保存生成时快照与当前状态，才能同时展示两套估值且保持稳定。
- 原生与外部市场价格记录必须包含来源、价格口径、来源数据时间、写入/导入时间、市场键和可用的样本数；不得只保存一个无来源数字。
- SavedVariables 的真正落盘时机受客户端控制；不能把内存更新等同于已经写盘。

## 19. 38002 API 与降级设计

### 19.1 主要依赖

| 能力 | 主要 API / 事件候选 | 设计边界 |
|---|---|---|
| 客户端 | `GetBuildInfo()` | 校验 build/interface，不代表全部功能已验证 |
| 生命周期 | `ADDON_LOADED`、`PLAYER_LOGIN`、`PLAYER_ENTERING_WORLD`、`PLAYER_LOGOUT` | reload 区分需要真机验证 |
| 角色 | `UnitLevel`、`UnitGUID`、阵营和服务器 API | 非 80 级严格关闭 |
| 墙钟 | `GetServerTime()`，会话内辅以 `GetTime()` | reload 后恢复不封顶的实际累计计时 `E` |
| 战斗 | `InCombatLockdown()`、`PLAYER_REGEN_ENABLED` | 只延迟弹窗，不执行受保护操作 |
| 任务 | `C_QuestLog`、`QUEST_ACCEPTED`、`QUEST_TURNED_IN`、`QUEST_LOG_UPDATE` | questID 查询可能异步或返回 nil |
| 当前 NPC | `GOSSIP_SHOW`、`C_GossipInfo.GetAvailableQuests()` | 只能看到当前 NPC，不能全世界扫描 |
| 物品 | `C_Item` / `GetItemInfo`、`GET_ITEM_INFO_RECEIVED` | 名称与售价可能异步加载 |
| 背包 | `C_Container`、`BAG_UPDATE_DELAYED`、金币变化事件 | 只能归因明确时间窗内的变化 |
| 专业 | `GetProfessions()`、`GetProfessionInfo()` 或 38002 对应接口 | 自定义专精/门槛允许手动修正 |
| 拍卖 | 原生拍卖行显示/结果事件与实际 38002 API | Todo 只监听用户搜索，不主动查询 |
| 外部估值 | 已加载插件公开只读 API；首个候选为 `Auctionator.API.v1.GetAuctionPriceByItemID` | 可选集成、无硬依赖；提供方与版本必须分别验证 |
| 团本 | `RequestRaidInfo()`、`UPDATE_INSTANCE_INFO`、保存实例与首领接口 | 必须异步等待，并用实测 ID 映射 |
| 重置 | `C_DateAndTime` 或 38002 对应日/周重置接口 | 无可靠接口时不能承诺瞬时识别 |
| AFK | `UnitIsAFK("player")`、`PLAYER_FLAGS_CHANGED` | 只能识别游戏 AFK 标志 |

38002 快照中 UI 只采用已核实模板：`BackdropTemplate`、`UIPanelButtonTemplate`、`UICheckButtonTemplate`、`InputBoxTemplate`。不依赖该快照不存在的 `BasicFrameTemplateWithInset`。

### 19.2 明确不能承诺自动准确识别

- 登录时枚举世界上全部未接日常；
- 未接取、未与 NPC 对话时知道今天具体专业轮换；
- 自动判定新任务固定、非限时、非轮换且适合单人；
- 所有服务器自定义前置和声望门槛；
- 当前区域、真实到达区域和实际移动路线；
- 并行任务间真实投入比例，平均分摊只是模型；
- 混杂背包变化中每件物品的准确来源；
- 仅凭金币变化判断来源；
- 所有多选奖励最终领取项；
- 拍卖行是否跨阵营统一或搜索是否覆盖整个市场；
- 外部拍卖插件私有数据库结构、未提供的来源扫描时间及其价格指标的真实新鲜度；
- 团队开组时间、能否成团和部分进度剩余耗时；
- 游戏 AFK 标志之外的真实挂机；
- 所有情况下绝对区分 `/reload` 与同角色重新登录；
- 运行时自动推断服务器阶段；
- 通过背包差值自动学习任务成本。

### 19.3 统一降级状态

每项自动能力必须呈现以下一种状态：

- **已验证**：API 存在且本客户端已经观察到有效数据；
- **可用但未观察**：API 存在，但玩家尚未触发场景；
- **已降级**：主路径不可用，正在使用明确备用路径；
- **不可用**：没有安全备用，该自动能力关闭。

核心降级规则：

- 任务 API 返回 nil：状态未知，不擅自标记未完成。
- 奖励归因含糊：本次实测作废，保留目录值。
- 拍卖只有聚合最低价：不写入 20 条中位数缓存。
- 外部提供方未加载或 API 不存在：隐藏导入动作或标记“不兼容此版本”，保留现有价格。
- 外部价格的 itemID、单位、市场或口径不明确：跳过该条；导入失败不得清空旧记录。
- 外部提供方不返回来源时间：保留导入值并显示“来源数据时间未知”，不能伪造更新时间。
- 团本只有实例锁定：显示进度未知，不推断全部完成。
- 周重置不可可靠获得：保留醒目提示，等待下一次可信刷新或用户修正。
- reload 不可可靠区分：预填设置并让用户选择继续，不静默恢复。

## 20. `/todo doctor`

### 20.1 命令

- `/todo`：打开主界面。
- `/todo help`：显示帮助。
- `/todo doctor`：显示兼容性与数据状态。
- 不提供直接清库命令；删除通过界面二次确认。

### 20.2 Doctor 检查项

**环境**

- build、interface、客户端版本、locale；
- Todo 版本、目录版本、schema 版本、最近迁移；
- 角色等级、角色键、服务器键、市场键；
- SavedVariables 是否完成一次 `/reload` 往返。

**任务与专业**

- questID 标题、任务日志、完成标记能力分别检测；
- 当前 NPC 可接 questID 读取能力；
- 最近一次 `QUEST_ACCEPTED`、`QUEST_TURNED_IN` 参数；
- 金币和物品奖励当前归因路径；
- 专业名称、技能值与次级专业识别；
- 目录中无法解析的 questID 摘要；
- 日常重置来源与可信状态。

**物品、奖励袋与拍卖**

- 当前容器 API 分支；
- 物品名称、商店售价、异步加载；
- 最近一次有效/作废开袋批次及原因；
- 当前拍卖 API 分支；
- Todo 是否保持“从不主动发起查询”；
- 最近用户搜索是否取得 itemID、逐挂单单位价、有效样本数和中位数；
- 空结果是否保留旧缓存。
- 检测到的外部提供方、插件版本、公开 API、适配器版本与市场范围；
- 提供方价格指标、来源时间能力、保护调用测试结果，以及可导入/缺失/跳过/错误数量；
- 当前外部提供方与实际生效来源优先级。

**团本与会话**

- `RequestRaidInfo()` 与 `UPDATE_INSTANCE_INFO`；
- P1–P5 及宝库实际 instanceID/encounterID 映射；
- 能否读取首领明细；
- 周重置来源；
- reload 区分、服务器墙钟、AFK 和异常样本；
- 会话开始墙钟、预设时长 `T`、实际累计计时 `E`、内部 `R` 与 `B`；
- 战斗中延迟弹窗；
- 非 80 级完全禁用。

## 21. 页面状态

| 页面/组件 | 状态 | 展示与行为 |
|---|---|---|
| 等级拦截 | 非 80 级 | 仅显示不支持提示，停止全部采集 |
| 自动弹窗 | 战斗中 | 不弹出，脱战后出现一次 |
| 会话设置 | 普通 | 预填上次模式、时长、区域；不提供本次目标或预计耗时输入 |
| 会话设置 | 数据未知 | 可稍后处理，不阻塞生成 |
| 本次计划 | 未生成 | 引导填写本次参数 |
| 本次计划 | 正常 | 展示统一计划列表、本次用时、路线、价值和进度 |
| 本次计划 | 无任务可放入 | 不强塞，展示最接近预算的候选 |
| 本次计划 | 超过预设时长 | `E/T` 继续累计并显示超出量；计划保留，`R=0` |
| 本次计划 | 计划预计超时 | 横幅警告，不自动删除 |
| 本次计划 | 数据变化 | 展示生成时与当前估值 |
| 本次计划 | 跨重置 | 标记基于重置前状态，等待用户重规划 |
| 全部候选 | 可执行 | 按任务效率排序 |
| 全部候选 | 状态未知 | 独立分组与标记 |
| 全部候选 | 数据不完整 | 展示阻止自动推荐的字段 |
| 全部候选 | 未解锁 | 灰显并说明条件 |
| 全部候选 | 今日已完成 | 折叠分组 |
| 全部候选 | 搜索命中 | 保留分组与组内排序，命中折叠组临时展开，显示匹配数量 |
| 全部候选 | 搜索无结果 | 显示无结果与清空搜索入口 |
| 估值数据 | 缓存存在 | 生效价格、提供方、口径、来源数据时间、导入/采集时间、样本数、手动备用价 |
| 估值数据 | 缺价 | 提示原生手动搜索、兼容插件导入或手动输入 |
| 估值数据 | 无兼容插件 | 不阻塞估值页，解释仍可使用原生缓存与手动价 |
| 估值数据 | 导入完成 | 展示成功、缺失、跳过、错误数量及逐项原因 |
| 估值数据 | 导入失败 | 旧记录保持不变，并显示提供方/版本/失败原因 |
| 估值数据 | 袋子无样本 | 价值 0 |
| 估值数据 | 袋子低样本 | 当前均值、样本数、低样本标识 |
| 设置 | 危险操作 | 分项清理；全部清除二次确认 |

## 22. 验收标准

### 22.1 兼容与等级

- [ ] 在目标客户端加载，TOC 为 38002，全流程无 Lua 错误。
- [ ] 79 级及以下无法使用 UI、推荐、计时、拍卖和开袋采集。
- [ ] 80 级战斗中登录不弹窗，脱战后只弹一次。
- [ ] `/reload` 能恢复时保持计划；无法确认时展示预填页而不静默恢复。
- [ ] 切换角色重新输入本次参数，角色数据互不污染。

### 22.2 会话与窗口

- [ ] “生成本次计划”只包含模式、至少可玩时长、手选开始区域和团本选择，不显示“本次目标”。
- [ ] 参数页以只读结果展示系统预计计划用时，不提供预计耗时输入框。
- [ ] 输入 `T=120` 分钟时，初始 `E=0`、`R=120`、自动规划预算 `B=102` 分钟。
- [ ] 累计 30 分钟后显示 `0:30 / 2:00`；重新规划使用 `R=90`、`B=76.5` 分钟。
- [ ] 累计 130 分钟后显示 `2:10 / 2:00` 和“已超出 10 分钟”；`R=0`，计划不清空，计时继续。
- [ ] 把 `T` 改为 180 分钟时 `E` 仍为 130；重新规划使用 `R=50`、`B=42.5` 分钟。
- [ ] 非常驻窗口 60 秒隐藏；悬停不暂停；有效操作重置窗口倒计时。
- [ ] 窗口隐藏、聊天、AFK 不暂停会话时间。
- [ ] “再玩 30 分钟”把 `T` 设置为当前 `E+30`，不重置累计用时。

### 22.3 推荐正确性

- [ ] 相同输入与数据快照产生完全相同结果。
- [ ] 自动算法最大化总明确净价值，而不是简单依次取最高任务效率。
- [ ] 推荐数量无上限，但自动内容不得突破 85% 预算。
- [ ] 固定保留项允许超时并停止自动追加。
- [ ] 工作日不自动推荐团本或单项超过 30 分钟的收益任务。
- [ ] 明确可执行任务先优化，状态未知只用剩余预算补充。
- [ ] 未知任务耗时、未知必需成本、未知必需路线不会自动入选，且不能通过手工输入耗时绕过。
- [ ] 同区域任务共享移动成本，首段“其他”明确标记未计入。
- [ ] 无任务能完整放入时不强塞。

### 22.4 计划稳定性

- [ ] 完成、跳过、价格变化、进度落后均不自动重排。
- [ ] 完成项保留原位；重规划后不再选入。
- [ ] 跳过项当前会话排除，下次真正登录恢复。
- [ ] 手动加入只追加到区域组末尾或路线末尾。
- [ ] 只有用户点击重新规划才改变成员、顺序或路线。
- [ ] 主计划不出现“本次目标”“本次重点目标”和“提前完成可追加”模块；团本以普通时间块行出现。
- [ ] 收益路线标题只显示任务与移动的合计分钟，不显示两者拆分；顶部计划总时长仍包含团本。
- [ ] 全部候选可按任务名、区域、专业、活动类型和 questID 检索。
- [ ] 多关键词按 AND 匹配；检索不改变分组和组内效率排序，清空后恢复完整列表。
- [ ] 搜索命中折叠组时临时展开；无结果时可一键清空。

### 22.5 时间学习

- [ ] 3 个并行任务运行 15 分钟时，各分配 5 分钟。
- [ ] 并行集合变化后按时间片重新分母。
- [ ] 丢弃一个任务样本时不把其时间重分配给其他任务。
- [ ] 区域移动与任务学习不重复累计。
- [ ] 未完成便跳过不保存有效任务样本。
- [ ] 每项只保留最近 20 个有效样本并取中位数。
- [ ] 超出 25%/400%、AFK、掉线、跨登录样本进入待确认。
- [ ] 样本作废不补回会话时间。
- [ ] 任务、移动和团本预计耗时均只读，无输入、修改或覆盖入口。
- [ ] 有有效样本时采用中位数；否则任务/移动采用内置参考，团本采用默认值。
- [ ] 开始、结束、交付与到达操作只更新学习样本，不直接修改当前冻结计划的预计耗时。
- [ ] 旧版本手动耗时字段迁移后不再参与计算。

### 22.6 估值与拍卖

- [ ] 物品使用拍卖税后价/手动税后价与商店价中更高的直接可变现值。
- [ ] 未知奖励按 0 并标记收益下限；未知成本不按 0。
- [ ] 多选一最多计算一项。
- [ ] 已有材料仍扣除机会成本。
- [ ] 声望、荣誉和未设置专业代币不增加金币价值。
- [ ] Todo 不发送任何拍卖查询。
- [ ] 用户成功搜索后，只有取得逐挂单数据才写入最低 20 条中位数。
- [ ] 不足 20 条展示实际样本数；空结果保留旧值；缓存不自动过期。
- [ ] 只有用户点击后才从兼容拍卖插件读取 Todo 所需 itemID；过程不发送拍卖查询、不遍历或复制对方全库。
- [ ] 导入记录显示提供方、插件版本、价格口径、市场键、来源时间或“未知”和导入时间；不得伪装成 Todo 的最低 20 条中位数。
- [ ] 同一物品严格使用“Todo 原生缓存 > 当前外部提供方 > 手动价 > 商店价”的来源优先级，不跨提供方平均。
- [ ] itemID、单位价、市场或口径不明确的记录被跳过；保护调用或部分导入失败不污染旧值。
- [ ] 外部记录不自动过期，只有再次导入、切换来源、删除或清理才改变。
- [ ] Auctionator 适配器只有通过 38002 真机测试后才标记兼容；TSM 与 Auctioneer 在未通过前只显示为未验证兼容槽。

### 22.7 奖励袋

- [ ] 无样本价值为 0；首个有效样本立即参与排名。
- [ ] 少于 5 袋显示低样本。
- [ ] 同类连续开启按实际袋数累计。
- [ ] 混入不同袋子或其他来源时整批作废。
- [ ] 切换服务器使用相同内容分布但按新市场价格重算。

### 22.8 团本

- [ ] 顺序严格为 P5 → P4 → P3 → P2 → P1 → 宝库。
- [ ] 黑曜石圣殿与永恒之眼为两个独立项。
- [ ] 不显示普通/英雄或人数选择。
- [ ] 25 人默认 120 分钟，宝库默认 30 分钟。
- [ ] 工作日不自动推荐；假期不足 3 小时只可能推荐宝库。
- [ ] 系统最多自动选择一个团本。
- [ ] 团本时间不重复叠加日常路线。
- [ ] 只有从零进度开始并在本次完整清团才写入完整耗时样本。
- [ ] 部分进度团本不要求用户填写剩余时间，使用系统保守估计并显示来源。

### 22.9 周期、目录与数据安全

- [ ] 日常重置清除今日覆盖，不清除价格、奖励袋和耗时。
- [ ] 周重置清除团本手动覆盖。
- [ ] 跨重置计划只标记失效，不自动改变。
- [ ] 目录更新保护手动非耗时字段、实测数据和历史耗时样本。
- [ ] 同 questID 本地任务与正式目录合并且不重复。
- [ ] 分项清理不误删其他类别。
- [ ] 全部清除必须二次确认，内置目录永不删除。

### 22.10 真机兼容门槛

在宣称“已兼容 38002”前，必须在 `_classic_titan_` 完成：

1. 80 级登录、生成、`/reload`、退出重登与切换角色；
2. 两个计划任务并行计时，交付一个后验证分母变化；
3. 固定奖励和多选奖励的可信归因；
4. 用户手动拍卖搜索，确认 Todo 未发查询且能否取得逐挂单数据；
5. Auctionator 候选适配器的版本、API、市场范围、价格口径、来源年龄、失败隔离与零查询；
6. 同类奖励袋批次成功、混杂批次作废；
7. P1–P5、黑曜石圣殿、永恒之眼和宝库实例/首领映射；
8. 跨日常与周重置；
9. 战斗中登录/重载；
10. 非 80 级完全禁用；
11. 开启脚本错误显示后完成全流程且 SavedVariables 无损坏。

### 22.11 视觉与独立性

- [ ] 未安装 ElvUI 时，Todo 所有页面、弹窗与交互完整可用。
- [ ] 安装 ElvUI 时，Todo 不依赖其加载顺序，不读取或修改其配置，也不产生全局样式冲突。
- [ ] 主计划、全部候选、估值数据和设置保持统一的深色、扁平、细边框与紧凑密度。
- [ ] 常用 UI 缩放比例与窄窗口下无文字遮挡、按钮截断或无法滚动区域。
- [ ] 悬停、按下、禁用、选中、成功、警告和错误状态均清晰，且状态信息不只依赖颜色。
- [ ] 38002 真机不出现缺失字体、材质或模板导致的 Lua 错误。

## 23. 设计完成边界

至此，Todo v1 的产品范围、用户流程、推荐优先级、时间预算、估值公式、路线、团本、页面、数据作用域、降级规则和验收条件全部冻结，没有待用户决定的产品问题。

进入开发前仍需完成以下事实核验，它们不是产品设计缺口：

1. 填充并逐项核实 P5 环境的固定日常与专业任务池目录；
2. 核实 38002 实际拍卖结果能否提供逐挂单单位价；
3. 核实任务金币、物品与多选奖励的可靠归因路径；
4. 核实日常/周重置 API 的实际语义；
5. 核实 P1–P5 与宝库的 instanceID、encounterID 和首领清单；
6. 核实泰坦时光服拍卖手续费与市场是否跨阵营；
7. 核实 reload 与同角色重新登录的可区分程度；
8. 在 38002 上核实 Auctionator 候选适配器，并建立 TSM/Auctioneer 的版本兼容矩阵；
9. 再开始技术设计、Lua 实现、真机测试和网易 DD 发布准备。
